# Short web posts

Choose **New → Short web post** in Campaigns. Write the body, save it as a draft, publish now, or choose a time in UTC. A short post has no visible title and always publishes on the website and in RSS, with no subscriber email. Its body and link destinations can contain up to 2,000 text characters; the raw source is limited to 20 KB. Markdown and rich text are supported, with the existing safe web renderer. HTML email documents, paid/audience blocks and live RSS blocks belong in an ordinary issue.

Short posts are public and bypass the optional subscriber gate. They use the publication's author and normal comment settings. They appear beside issues in the archive; their cards use a plain excerpt and a short-post label. RSS items carry a description and full safe body without a title element. Public Markdown endpoints return the body without a heading. Search, share cards, slugs and the private dashboard use an automatically derived excerpt, with a generic fallback for an empty draft. There is no separate reader app, social feed or promise of reach.

The dashboard, REST and MCP use the existing campaign actions. `create_campaign` accepts `kind: "note"`; the default is `issue`. Kind stays fixed. `list_campaigns` can filter by kind. Short posts always have `publishTo: "web"` and audience `all`. Attempts to give them an email target, title, subtitle, subscriber targeting or subject test are refused. Test emails are refused too. The normal send permission, agent approval and account checks apply to publishing and scheduling. The existing scheduling job publishes the page without creating recipient messages or consuming email deliveries. The global sending switch still applies, as for existing web-only issues.

The short-post editor saves drafts through `update_campaign` and published bodies through `update_published_issue`. A published edit retains its address and original publication date, refreshes the excerpt and updates the sitemap's modification time. The existing 30-version history and restore actions work for short posts. Copying a post creates another web-only short-post draft. Bulk tags and guest author assignment remain the existing campaign operations. Private account exports mark notes with `kind: "note"` in frontmatter and manifest metadata. Ordinary issue exports retain their existing format. Existing campaign webhook events include `kind: "note"` for notes.

## A weekly digest draft

Choose **New → Draft this week's short-post digest**, or call `create_short_post_digest`. It snapshots this publication's public, listed short posts from the preceding seven days into a normal newsletter issue draft, oldest first, with full public bodies and links. The API can choose one to seven days. Unlisted posts, drafts, old posts, private audience content and other accounts' posts are excluded. A window with more than 20 posts is refused; choose fewer days rather than silently omitting posts. A stable external ID returns the same draft on retry, including concurrent retries. The original note IDs and window are included in the response and private export metadata.

Review and edit this ordinary issue draft, then explicitly send or schedule it with the existing campaign controls. Drafting does not queue a job, email anyone or enable a recurring send. The digest is a snapshot: later edits to a short post do not change an already drafted email. Normal subscriber preferences, limits, checks and agent approval govern any eventual send.

Migration `0038_short_posts.sql` adds one campaign lookup index; it has not been applied to production by this local build. No new Worker, provider, bucket or recurring job is required.
